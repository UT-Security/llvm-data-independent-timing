Paper experiment 03 · mbedTLS

Fine Grain Crossover

Region placement beats whole-function placement by up to 13.84% — and every point of it is IPC on an identical instruction stream. Below about 2.5 µs of work per secret region the advantage reverses and both lose badly to blanket.

crossover at ~2.5 µs/region Apple M5 · kperf 5 arms · 5 sizes · 2 modes gem5 pending
Why this is not experiments 01 and 02 again

Nothing before could measure fine grain

Experiments 01 and 02 both ask pass versus blanket along the secret-fraction axis. Neither has a whole-function arm, and neither could have used one: in both, the public and secret work live in different functions, so -taint-dit-placement=function would have produced the same coverage as region placement. There was nothing for it to do.

This experiment puts both kinds of work in one seeded function, which is the only structure where the two policies can diverge — and checks that they actually do, rather than assuming it. Each arm reads PSTATE.DIT inside that function, before the public work:

Region placement

-ftaint-harden

Enables DIT after the public loop. The bookkeeping runs unprotected.

public work covered0.000

Function placement

-taint-dit-placement=function

Enables DIT at entry. The whole body is covered, bookkeeping included.

public work covered1.000
;; region                              ;; function
  b.lt  ...  ┐ public loop          msr   DIT, #0x1   ← at entry
  b.ne  ...  ┘ runs DIT-OFF         b.lt  ...  ┐ public loop
  msr   DIT, #0x1  ← after it       b.ne  ...  ┘ runs DIT-ON
  msr   DIT, #0x1                     msr   DIT, #0x1
  msr   DIT, #0x0                     msr   DIT, #0x0
  ret                                 ret

Three mode writes either way. Only the first one moves. That detail turns out to be the entire result.

And the knob is region size, not secret fraction: 8 MB total held fixed, f_secret held at 54–74%, chunk swept 64 B to 16 KB so the region grows 256× while the region count shrinks by the same factor.

Result

The crossover is in region size

mbedTLS 3.6.2 HMAC-SHA256, 7 rotated paired reps per point, median. Wall-clock is the headline: unlike experiment 02, the arms are different binaries, so IPC is not the inverse of time.

The floor matters as much as the ceiling. At 0.66 µs regions, blanket costs +10.75% while region costs +47.47% and function +49.21%. Below roughly 2.5 µs, selective placement of any granularity is the wrong choice — region placement is 33% worse than simply leaving DIT on everywhere.

That puts a measured number on a belief the project has carried from a single QuickJS data point (“fine grain stops paying below ~1 µs per region”), and places it somewhat higher.

The nop arm spans −1.67% to +0.07% throughout, so none of this is the layout cost of inserting the switches.

Mechanism

Every point of it is IPC

Instruction counts between the two placements are identical to ±0.00% at every point. Both execute exactly three mode writes per record. Region placement is not doing less work — it is doing the same work faster, because the public loop keeps its value prediction.

With equal instruction counts the time delta must be exactly 1/IPC. It is:

Agreement within 0.1 points everywhere. Note also that function placement’s IPC is nearly flat at 2.22–2.28 across a 256× change in region size, while region placement’s climbs from 2.250 to 2.643. Covering everything costs the same wherever you do it; narrowing pays more the more there is to narrow.

The design gate that killed the first attempt

Inter-record ILP hides the prize

The original public lane was a TLS proxy demux: hash lookup plus chain walk per record, chosen because pointer chasing is the shape that carries the prize in 01 and 02. It failed the headroom gate — and the reason generalises.

configurationno DITblanketpenaltysign test
chain=16, independent records125.6 ms118.9 ms−5.36%0/9
chain=16, records chained249.3 ms344.1 ms+38.01%9/9

Same code, same table, same access pattern. The only change is whether record r+1’s work depends on record r’s result. A real demux is embarrassingly parallel across records, so the out-of-order engine overlaps a dozen of them and each per-record chain of ~8 loads is hidden. Value prediction has almost nothing left to add, so DIT costs almost nothing to remove it.

The win condition needs a fourth clause. The project already knows headroom requires a serial dependence chain. This adds that the chain must span the unit of work: per-unit chains get overlapped away. It is why coin selection works in experiment 01 — a solver’s search is serial across the whole call — and why image filters never did.

It also means experiment 02’s public lane sits at the favourable extreme of this axis: one unbroken chain thousands of iterations long with zero ILP. Its +30.6% is real, but it is not what request-processing code looks like.

Found on the way

A hardened build with zero switches, and no error

The mbedTLS source tree carries 107 stale object files and three archives from an earlier in-tree build, and the existing build script copied them with tar --exclude=.git. make then judged every object up to date and skipped every compile: the taint flag is passed, nothing is recompiled, and the result is a library with zero msr DIT and no diagnostic of any kind.

Fixed in both this experiment’s script and tls_handshake/build.sh, which had the same latent bug. Anything built from that tree before 2026‑09‑01 is worth re-checking.

Open

What is still missing

gem5. Silicon says the gain is IPC; it cannot say which structure produces it. Feature isolation would attribute it directly, and a switch-model sweep matters more here than in experiment 02 — the toggle rate at chunk=64 is one mode write per ~700 instructions, where 02’s was 49 per signature.

The public lane is still synthetic in the same way 02’s is. The secret lane is a real library primitive and the interleaving is the realistic part, but the bookkeeping loop is constructed.

One anomaly. The dep mode at chunk=1,024 reads −1.79% where ilp reads −7.56%, against a smooth trend everywhere else. Unexplained.
