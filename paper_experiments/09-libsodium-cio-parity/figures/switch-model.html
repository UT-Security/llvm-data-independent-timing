The Cost Is the Switch

Take the hardened binary that costs +81.85% on libsodium's chacha20-poly1305, change nothing about it, and run it on a core that renames the MSR DIT write instead of serialising it. The overhead becomes −0.28%. Same code, same input, one mechanism — and it accounts for essentially all of it.

Why this experiment needed a simulator. An Apple M5 has exactly one MSR DIT implementation and it serialises. The silicon run could only infer this decomposition, by dividing measured cycles by measured switches — a ratio that reproduces its own input, as its write-up says plainly. Turning the mechanism off is the one thing hardware cannot do.

What a switch costs

difference between two binaries that differ only in whether it executes

Each policy ships a twin: identical placement, identical instruction count, byte-identical addresses, HINT #0 in place of every MSR DIT. Subtracting the twin leaves the switch and nothing else — a measurement rather than a ratio of one measurement against itself.

This rig's own marker cost was measured the same way and is 6 cycles; correcting it out would move every result by at most 0.28 points.

Two findings this run overturned

both were ours

Neither was caught by inspection. Each needed a control that did not exist when the claim was made.

argon2id is free because 191M cycles amortise every switch
The toggle rate is low, but not through amortisation: taint never reaches the hashing kernel. argon2_hash stores the password pointer into a stack-allocated argon2_context; that store transfers nothing, so argon2_ctx receives a clean pointer and argon2_fill_memory_blocks — essentially all 191M cycles — carries zero switches and appeared in no report. It is protected only because CIO's config over-taints a variant flag, whose region happens to span the calls. A new memory information-loss category now reports the gap.
Finer placement wins on aes256-gcm decrypt
Inserting a switch moves all downstream code by exactly 4.00 bytes; after 524 switches that is 34 cache lines of displacement, worth −6.94% to +4.52% — larger than the policy differences being measured. The finer policy had simply drawn a favourable layout. Against a per-policy layout twin it is 3.2 points worse, executing more switches at the same dwell. Two mechanisms were proposed for the original result before the controls falsified both.
Found independently on silicon, in parallel. Experiment 09 added the same control on both Apple hosts — arm Z, a NOP-switch layout twin — and it reads 1.0769× on M5 and 1.0870× on M4 for aes256-gcm encrypt, the same benchmark where the term is largest here. Three machines, two instruments, same effect on the same row. A 7–8% layout term on real silicon is not a simulator artifact: it is what instrumenting a 252-tick region costs through code movement alone, and an A-vs-P comparison books it as DIT cost.
The headline is immune to this. Renamed versus serialising is one binary under two machine configurations, so layout cancels identically. It is the only comparison in the study with that property — which is a good reason it is the one carrying the result.

Why the numbers are readable

deterministic simulation — exact checks, not medians

gem5 replays bit-identically, so the silicon run's 15-rep median is replaced by checks that either hold exactly or fail. All of them hold, across 240 runs.

Two gates were themselves wrong, and both were caught by other gates. Requiring ditSuppressed > 0 as evidence the mode was active failed 16 of 24 AES-GCM cells as false alarms — AES offers computation-simplification nothing, so it reads zero while the mode is provably set. And the mode-readback probe was itself a confound: a single MRS DIT anywhere in a timing binary decodes differently under the two models, shifting ed25519 by 0.35% from an exit-time destructor.

What this does not say

limits, recorded
3 vs 85

Committed switches per signature from the shipped per-TU flag against the whole-library configuration measured here. Taint cannot cross a translation unit, so the mode is set once and inherited. Both are sound; they are not the same operating point.

~3×

gem5 magnitudes run inflated against silicon throughout this project. Ordering and proportionality transfer; absolute percentages do not.

~10 pts

The resolution limit for comparing two different policies, even with layout twins. Differences of 20–50 points are resolvable; one point was never resolvable in this rig.

2 patches

gem5 lacked PMULL at 64×64→128, so AES-GCM could not run at all; it was added and validated against this host's own hardware. ditCycles is the second. Neither is upstream.
