What the oracle sees

Taint is seeded on the key with an m5 op and propagated at commit, so the oracle sees the real dynamic trace rather than speculation, and flags any DIT-covered instruction that consumed a secret with the mode clear.

The unhardened control is what makes this meaningful: it registers 4,647,818 secret ops running clear, so the oracle demonstrably can see them and the hardened arm’s 40 is not an instrumentation failure. Those 40 are a declassification point — the harness consuming the signature — not a leak.

The layout term not resolving is load-bearing: the cost here is DIT actually running, not the code-shape change of inserting switches. All four NOP gates pass — an inert NOP control does not fail loudly, it silently reads as “layout is everything”, which is how an earlier result in this project had to be retracted.

Note the direction: coarse beats fine, +0.167% against +1.963%. Signing is secret work end to end, so there is no public lane to uncover and narrowing pays its toggles for nothing. Consistent with experiment 03’s floor.

The heap variants exist because the module-wide secret-global rule closed C1/C3/C4 by covering their shared delivery route — all four probe buffers were static globals — rather than their mechanisms. On the heap they fail identically, which is how we know the three defects are storage-independent.

So the soundness claim is a property of libsecp256k1, not of the analysis. Six mechanisms leak by construction; that library contains none of them.

Two ways this probe misled, both now guarded

Its consume_all accumulated every consumer’s secret-derived return into one local, so once one channel started working the first call tainted it and placement blanketed all seven — reporting everything clean. Note the direction: fixing C2 is what broke the harness. While every channel was broken no return was recognised as secret, and it discriminated by accident.

And ditseen[] samples DIT at entry, which cannot separate “unprotected” from “self-instrumented, enable comes later”. Read the oracle’s per-PC list.
